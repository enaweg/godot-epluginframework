# Add-ons that build_godot_addons.cs always lists, in addition to the ones it finds, whatever their stars or activity.
# One per line: "slug;url", or just "url" to let generate_known_plugins.cs find the slug.
# - url:  the git repository: GitHub, GitLab or Forgejo (Codeberg; also self-hosted GitLab, Forgejo and Gitea) or any other
#         git host. A repository's tag or release page works too. On any other host, give the URL ending in .git that the
#         updater can read.
# - slug: the add-on's folder in res://addons. It wins over the folder found in the release ZIP or the repository.
# The add-on still needs a release or version tag (an optional "v", then 1.2 or 1.2.3, optionally a prerelease suffix such
# as "-beta.1"), or it is left out.

# ePlugins listed in the README. Their repositories also carry the add-ons they depend on (ePlugin, eLogger, eContainer,
# gdUnit4), so the slug names the plugin's own folder.
eContainer;https://github.com/enaweg/godot-econtainer
eLogger;https://github.com/enaweg/godot-elogger
eMessagePipe;https://github.com/enaweg/godot-emessagepipe
global_asset_manager;https://github.com/sn1ks0h/Global-Asset-Manager
# A GDExtension whose libraries are built by CI (only in the release ZIP). Neither the ZIP nor the repository has a
# plugin.cfg, so ePlugin updates it as a GDExtension add-on, found by its folder name.
godot_servo;https://github.com/shiena/godot-servo
# A GDExtension plugin whose libraries are built by CI: they are in the release ZIP but not in the repository, so its
# update site must be the releases page (which build_godot_addons.cs takes for any GitHub repository with releases).
rider-plugin;https://github.com/JetBrains/godot-support
# Its release ZIP ships a GDExtension without a plugin.cfg, which ePlugin updates as a GDExtension add-on.
tweens_gd;https://github.com/outfox/tweens.gd
